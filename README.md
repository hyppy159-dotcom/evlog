# EV 차계부 (EvLog)

폴스타4 같은 **안드로이드 오토모티브(AAOS) 차량 화면**과 **일반 안드로이드 휴대폰**에서
모두 돌아가는 전기차 차계부 앱입니다. 같은 APK 하나로 둘 다 설치됩니다.

- 차 안에서는 차량 API로 **배터리 잔량·속도·충전구 상태·주행가능거리**를 직접 읽습니다.
- 휴대폰에서는 **GPS**로 주행을 기록하고, 충전은 직접 입력합니다.
- 인터넷 연결이나 서버 없이 **기기 안에만** 저장됩니다.

---

## 1. APK 만드는 법 (안드로이드 스튜디오 없이)

깃허브에 올리기만 하면 깃허브가 대신 빌드해서 APK를 만들어 줍니다.

0. 받은 `EvLog-project.zip` 의 **압축을 먼저 풉니다.** (깃허브는 zip을 자동으로 풀어주지 않습니다.)
1. 깃허브에서 **New repository** → 이름 아무거나(예: `evlog`) → **Private** 선택 → Create.
2. 만들어진 저장소 화면에서 **uploading an existing file** 링크 클릭.
3. 압축을 푼 폴더의 **내용물 전체**를 드래그해서 올립니다.
   - 폴더째로 올리면 됩니다. `.github`, `app`, `gradle`, `keystore`, `gradlew` 가 모두 포함돼야 합니다.
   - 파일 탐색기에서 숨김 파일이 안 보이면 보기 설정에서 숨김 항목 표시를 켜세요 (`.github` 가 숨김 폴더입니다).
4. **Commit changes** 를 누르면 빌드가 자동으로 시작됩니다.
5. 상단 **Actions** 탭 → 방금 실행된 `Build APK` 클릭 → 3~5분 기다립니다.
6. 초록색 체크가 뜨면 그 페이지 아래 **Artifacts** 의 `EvLog-APK` 를 내려받습니다.
   압축을 풀면 `EvLog-v1.apk` 가 나옵니다.

이후에 코드를 고치고 다시 올릴 때마다 새 APK가 자동으로 만들어집니다.

### 안드로이드 스튜디오가 이미 있다면

폴더를 그대로 열고 `Build > Build Bundle(s) / APK(s) > Build APK(s)` 한 번이면 끝입니다.
결과물은 `app/build/outputs/apk/release/` 에 생깁니다.

## 2. 설치

### 휴대폰

내려받은 APK를 휴대폰으로 옮겨 실행하면 됩니다.
"출처를 알 수 없는 앱" 설치를 한 번 허용해 주어야 합니다.

권한은 **위치(항상 허용)** 와 **알림** 두 가지가 필요합니다.
위치를 "앱 사용 중에만"으로 두면 화면이 꺼졌을 때 주행이 끊겨 기록됩니다.

### 차량(AAOS)

여기가 가장 까다로운 부분입니다. 폴스타·볼보의 양산 차량은 보통
**개발자 모드와 ADB가 잠겨 있어 사용자가 임의로 APK를 설치할 수 없습니다.**
차량에 넣으려면 셋 중 하나가 필요합니다.

1. 차량 설정에 개발자 옵션이 열려 있고 USB/무선 ADB가 허용되는 경우
   → `adb install EvLog-v1.apk`
2. Google Play 스토어(오토모티브)에 개발자 계정으로 올려서 내 차에 내려받는 경우
3. 제조사 개발자 프로그램에 등록된 개발 차량/에뮬레이터

**먼저 확인해 보시길 권합니다.** 확인 방법은 차량 설정 → 시스템 정보에서
빌드 번호를 여러 번 눌러 개발자 옵션이 열리는지 보는 것입니다.

당장 차량 설치가 막혀 있어도 앱은 그대로 쓸 수 있습니다.
휴대폰에 깔면 GPS 기반으로 주행 기록·전비 통계·충전 가계부가 모두 동작합니다.

### 오토모티브 에뮬레이터로 먼저 시험하기

안드로이드 스튜디오의 Device Manager에서 **Automotive** 계열 이미지를 받아 실행하면
차량 데이터(속도·잔량·충전구)를 흉내 낸 상태로 앱을 확인할 수 있습니다.
에뮬레이터 확장 컨트롤의 **Car data** 패널에서 값을 직접 바꿔 볼 수 있습니다.

## 3. 기능

| 화면 | 내용 |
|---|---|
| 대시보드 | 배터리 잔량 게이지, 주행가능거리, 현재 상태, 이번 달 주행·충전비, 평균 전비, 최근 12회 전비 추이 차트 |
| 주행 | 자동 기록된 주행 목록 (거리·전비·소요시간·평균/최고 속도·잔량 변화). 길게 누르면 삭제 |
| 충전 | 자동 기록된 충전 + 직접 추가 (충전량·완속/급속·요금·메모). 길게 누르면 삭제 |
| 설정 | 배터리 용량, 완속/급속 단가, 급속 판정 기준, 최소 주행거리, 자동 시작, CSV 내보내기, 전체 삭제, NAS 서버 연동 |
| 주행 중 모니터 | 배터리·주행가능거리·이번 주행 거리·현재 전비를 큰 글씨 네 칸으로. 주행 중에도 보이도록 만든 전용 화면 |
| 주행 경로 | 주행하는 동안 위치를 남겨 두었다가, NAS 서버로 올리면 웹 지도에 속도별 색으로 그려집니다 |
| 차량 데이터 진단 | 차량에서 어떤 값을 읽을 수 있고 무엇이 막혀 있는지 앱이 스스로 점검해 보여줍니다 (메뉴 → 차량 데이터 진단) |

### 주행 중 모니터

안드로이드 오토모티브는 주행 중에 "운전 방해 최적화"로 선언되지 않은 화면을 가려 버립니다.
그래서 목록도 스크롤도 없이 숫자 네 개만 크게 보여주는 전용 화면을 따로 두었습니다.
화면이 꺼지지 않도록 KEEP_SCREEN_ON 도 걸려 있습니다.

여는 방법은 대시보드의 **주행 중 모니터 열기** 버튼, 또는 주행·충전 중에 뜨는 **알림 누르기** 입니다.

차량 제조사가 사이드로딩한 앱을 주행 중 아예 허용하지 않는 정책을 쓰면
이 선언만으로는 안 될 수도 있습니다. 그 경우 차가 멈춰 있을 때만 화면을 볼 수 있습니다.

### NAS 서버 + 휴대폰에서 보기

주행·충전·경로를 시놀로지 NAS에 모아 두고 휴대폰 브라우저로 볼 수 있습니다.
설치할 패키지가 없는 작은 파이썬 서버와, 지도가 들어간 웹 화면이 server 폴더에 있습니다.
설치 방법은 **server/README.md** 를 보세요. 지도는 OpenStreetMap이라 API 키가 필요 없습니다.

앱 설정 아래쪽 **NAS 서버 연동**에 서버 주소와 토큰을 넣고 저장하면
주행이 끝날 때마다 자동으로 올라갑니다. 실패하면 그대로 두었다가 다음에 다시 시도하고,
같은 기록을 여러 번 올려도 서버에서 중복되지 않습니다.

### 자동 판정 규칙

- **주행 시작**: 속도가 4 km/h를 넘을 때
- **주행 종료**: 정차가 3분(차량 데이터) 또는 5분(GPS) 이상 이어질 때, 시동이 꺼질 때, 충전기를 꽂을 때
- **거리**: 차량에서는 속도를 적분해서, 휴대폰에서는 GPS 좌표 사이 거리로 계산합니다
  (주행거리계는 시스템 앱만 읽을 수 있어 쓰지 않습니다)
- **충전 시작/종료**: 충전구 연결 상태로 판단하고, 그 값을 못 읽는 차량에서는
  "정차 중 배터리가 1% 이상 상승"으로 판단합니다
- **완속/급속**: 세션 중 최대 출력이 설정값(기본 15 kW) 이상이면 급속
- 300 m 미만 주행, 0.4 kWh 미만 충전은 저장하지 않습니다 (설정에서 조정 가능)

### 저장·백업

기록은 기기 안 SQLite에 저장됩니다.
설정 화면이나 우측 상단 메뉴의 **CSV 내보내기** 로 주행·충전 파일 두 개를 뽑아
메일이나 드라이브로 보낼 수 있습니다. 엑셀에서 한글이 깨지지 않게 저장됩니다.

## 4. 알아 두면 좋은 점

- **서명 키가 저장소에 함께 들어 있습니다** (`keystore/evlog.jks`).
  덕분에 어디서 빌드하든 서명이 같아서, 새 APK를 기존 앱 위에 덮어 설치할 수 있습니다.
  개인용이라 이렇게 두었습니다. 스토어에 올릴 거라면 키를 새로 만들고
  `app/build.gradle` 의 비밀번호를 깃허브 Secrets로 옮기세요.
- **주행거리계(오도미터)** 는 `CAR_MILEAGE` 권한이 시스템 앱 전용이라 읽을 수 없습니다.
  그래서 총 주행거리는 이 앱이 기록한 값의 합계입니다.
- **웹 차계부 연동, 주행 경로 지도, 주차 사진, 소모품 관리** 는 이번 버전에 없습니다.
  경로 지도는 지도 SDK 키가, 웹 연동은 서버가 따로 필요합니다.

## 5. 프로젝트 구조

```
app/src/main/java/com/jhkim/evlog/
├─ MainActivity.java          탭 3개 + 권한 요청
├─ SettingsActivity.java      설정
├─ Prefs.java                 설정값
├─ db/                        Trip, Charge, Db(SQLite)
├─ vehicle/
│   ├─ CarApiSource.java      android.car 를 리플렉션으로 읽음 (차량 전용)
│   ├─ GpsSource.java         GPS 위치·속도
│   └─ SourceManager.java     둘을 합쳐 하나의 스냅샷으로
├─ logger/
│   ├─ LoggerService.java     1초마다 도는 포그라운드 서비스
│   ├─ TripRecorder.java      주행 시작·종료 판정
│   ├─ ChargeRecorder.java    충전 세션 감지
│   └─ LiveState.java         화면에 뿌릴 현재 상태
├─ ui/                        화면, 게이지·차트 커스텀 뷰
└─ util/                      숫자 표기, CSV 내보내기
```

차량 API를 리플렉션으로 부르는 이유는, `android.car` 라이브러리가 차량에만 있어서
직접 import 하면 휴대폰에서 앱이 죽기 때문입니다. 이 방식이면 APK 하나로 둘 다 됩니다.
